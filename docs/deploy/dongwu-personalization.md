# @DONGWU：减少重复试错的偏好记忆方案

## 当前行为

当前每次模型请求读取本次提示词、需要保留、图片及用途、模式、模板和所选版本。历史记录用于保存和恢复，不会自动变成下一次请求的个人记忆，也不会自动训练或微调模型。仅增加使用次数，不会让当前实现持续学习偏好。

## 建议分两步实现

### 第一步：用户确认的偏好卡

在“我的偏好”明确选择启用，逐条保存、编辑或停用规则。先支持三类：

- 产品底线：白底产品的几何、结构、按钮、标识与颜色不变；不要擅自美化产品。
- 工作习惯：KeyShot 产品补场景时保持机位，先匹配支撑面、透视、尺度、接触阴影和环境反射。
- 输出偏好：默认中英完整提示词、固定/可变要素、图间职责、负向约束和可执行参数建议；避免空泛质量词。

从已接受成果中点“把这一条记为偏好”，展示拟保存的短规则，用户确认后再写入。不要把失败、未采用或仅浏览过的结果默认为喜好；不要自动保存原图、会话、密钥或整段私人工作资料。

实现上新增独立 `ps_preferences` 用户隔离表，启用 RLS，仅用户本人读取和管理。团队通用规范另用管理员维护的独立规则集，不能读取其他人的私人偏好。用户可以关闭记忆，也可以逐条清除。

每次调用只带入适用的少量规则，并显示“本次采用的偏好”。本次明确要求和“需要保留”优先于历史偏好；产品身份依据、成员权限、系统安全边界不可被偏好或案例覆盖。冲突应指出，不应偷偷替用户做决定。

### 第二步：按任务检索已接受的案例

当积累了约 20 份明确采用的成果后，再增加“采用 / 不采用 / 需要修改”反馈。先用 PostgreSQL 的标签与全文搜索检索任务相近的 2～3 个已接受案例，例如“产品补场景”“人物互动”“参考图光影迁移”。首版无需新增付费数据库、向量服务或训练任务。

案例只提取解决办法与约束摘要，默认不附原图，不将某次具体产品、人物、标识或场景误当成永久偏好。相似度低、案例有冲突时不带入。私人案例只对本人可用，主动发布到团队库的案例才允许团队复用。

## 降低成本的配套措施

1. 使用前检查图号是否齐全、主体与场景用途是否冲突；能在本地发现的问题不发起付费请求。
2. 模板预设、灵感卡和手动偏好编辑不调用模型。分析与生成仍分开计次，用户自行决定是否需要分析。
3. 一个请求 ID 只执行一次；网络中断先查询结果，不自动重跑。不要为了“学习”后台批量调用模型。
4. 只在用户主动要求时执行较长的案例总结，提前说明会消耗一次额度；首版不自动开启。

## 验证是否确实更省成本

先记录 20 个常见任务作为基线，对比开启偏好后的同类任务：首次采用率、得到可用提示词前的平均调用次数、重复纠正同一问题的次数、人工修改量。以“每份被采用成果消耗多少调用”为主要指标，不能用分数变高代替用户采用。

检查关闭偏好后是否恢复当前行为；更换用户后是否完全隔离；本次要求是否能覆盖历史偏好；旧案例是否会带入错误产品、人物或图号。出现负面迁移时，应能定位到具体规则并停用。

本文件是后续方案。本次升级不会收集反馈、创建个人记忆或执行训练；需要用户确认功能范围后再实施。

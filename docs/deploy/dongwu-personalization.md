# @DONGWU：精简文字经验与后续个性化

## 已实现的第一阶段

用户在“创作经验”中明确添加、确认并启用规则后，后续创作才会读取这些经验。系统不自动把作品、失败结果、浏览记录或原图加入记忆，也不训练或微调模型。保存经验不额外调用模型。

每人只有一个私人文字档案：最多12条规则，每条280字，总体积不超过16KB。只保存标题、规则、任务类型和适用模板，不附图片或完整提示词。重复规则会提示合并。每次最多选择4条匹配本次任务和模板的规则，显示所采用的经验标题，避免整份历史进入模型上下文。

提供可编辑的参考写法：产品外观锁定、场景透视与接触关系、完整中英输出。参考写法必须由用户选择、确认和启用，不能默认为个人喜好。适用范围可选参考图、文字或全部任务，以及某个模板。

本次明确要求、需要保留和参考图事实优先于历史经验。经验只是辅助文字，不是图片证据，不能借此猜测产品功能、替换图号或访问外部地址。经验参与分析上下文绑定；修改适用经验后，旧建议会过期。历史版本保留当时采用的文字上下文，便于核对。

经验可关闭、编辑、移除，并包含在个人文字导出中。数据放在独立 ps_memory 表，RLS 只允许本人读取；写入由验证成员资格的后台完成。管理员不能自动读取其他成员的私人经验，团队库发布不会附带私人经验记录。

## 新参考图的存储

新图只保留在当前浏览器页面，分析时随请求发给独立函数及模型，不写入工作室云端图片桶。云端仅留图号、角色、说明及校验哈希等文字。关闭或刷新后，需要重新选择原文件才能继续看图分析；缺图时不会静默改为猜图，也不会发起模型请求。

此前上传的旧图保留，不自动删除。图片是否被第三方模型提供商保留取决于该提供商政策，不在本应用的存储保证内。Base64 仅用于本次传输，不作为长期存储或个人记忆。

完整作品、版本和分析仍作为私人文字历史保存，因此历史空间仍会增长；16KB只约束精简经验，不能当作整个应用的空间上限。

## 后续第二阶段：精选案例摘要

积累约20份明确采用的成果后，可再加入“采用 / 不采用 / 需要修改”反馈与案例检索。只提取可复用的任务、硬约束、解决方法和采用理由；不保存原图、人物身份、密钥或整段对话，也不把失败结果当成偏好。私人案例仅本人可用，主动发布的团队案例才允许团队复用。

首版可先用任务标签与数据库全文搜索选取2～3个相关摘要，无需新增付费向量服务或训练任务。相似度低、有冲突时不带入。本次仅实现手动确认的经验规则，自动案例提炼与检索尚未启用。

## 判断是否减少试错

以真实常见任务比较开启经验前后：首次采用率、每份可用成果的平均调用次数、重复纠正同一问题的次数、人工修改量。模型自评分变高不能代替用户采用。关闭经验后应恢复仅按本次输入工作的方式；更换成员后完全隔离。
